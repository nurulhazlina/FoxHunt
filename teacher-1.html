Module 1 of 5 — Teacher Guide

Morse Code & Beacon IDs — Facilitator Notes

Teaching guidance, answer keys, common mistakes, and facilitation tips for Module 1.

📚 1. What This Module Teaches

Learning Objectives

  • Understand the physical structure of Morse code (dit/dah timing ratios).
  • Identify the five ARDF beacon callsigns (MOE, MOI, MOS, MOH, MO5) by counting dits.
  • Explain the 5-minute ARDF beacon cycle (12s TX + 60s rest).
  • Implement a basic Morse player using the Web Audio API (AudioContext, OscillatorNode).
  • Evaluate code for timing correctness and debug logical errors.

Key Concepts Covered

  • Web Audio API — AudioContext, createOscillator, frequency, connect, start/stop.
  • Morse timing — DIT = 80 ms, DAH = 240 ms (3× ratio), inter-element gap = 80 ms.
  • ARDF beacon protocol — 5 beacons, 700 Hz carrier, 12s TX slots, 60s MO rest.
  • Computational thinking — decomposition (symbols → timing), abstraction (pattern string).

Prerequisites

  • Module 0: Orientation (what is ARDF, safety, equipment overview).
  • Basic JavaScript familiarity (variables, loops, functions) is helpful for Tier 3+.
Time estimate: 45–90 minutes depending on prior JavaScript experience. Tier 1+2+MCQ is accessible to all scouts. Tier 3 requires ~15 extra minutes for JS learners.

🔊 2. Interactive Demo Guide

Using the Morse Player (Section 2 of module-1.html)

The player uses the Web Audio API. Each "▶ Listen" button creates a new AudioContext and schedules oscillator start/stop times in advance (not setTimeout-based). This is important for accurate timing — tell scouts not to spam-click buttons.

Browser Autoplay Policy: Modern browsers (Chrome, Firefox, Safari) block AudioContext creation until the user has interacted with the page. The Morse player already requires a button click (a user gesture), so this is handled correctly. However, if a scout loads the page and immediately runs console code, AudioContext may be suspended. Fix: call audioCtx.resume() after creation in any console experiments.

Common Audio Issues

  • No sound on iOS: Ensure the device is not on silent mode (hardware switch). iOS requires a user gesture — the button click satisfies this.
  • Clicking/popping sounds: Normal for rectangular on/off oscillators. This is a feature of Morse — scouts will experience the real thing.
  • Firefox older versions: webkitAudioContext fallback is included.

Timeline Simulator (Section 3)

The canvas animation runs at 10 seconds real-time to represent the 300-second cycle. The progress indicator shows current position. If a scout asks why it is "too fast", explain that it is a sped-up demonstration — the real cycle takes 5 minutes.

Code Tab Reference (Section 5)

The three tabs show Morse patterns, timing constants, and the complete playMorse function. These are intentionally shown — scouts in Tier 3 are asked to recreate this function, not copy it. Encourage them to close the tab before attempting Tier 3.

Tier 2 — Debug Exercises: Sample Good Responses

Exercise 1

Pattern claimed for MOI: -- --- .

What is wrong: That is the pattern for MOE (1 dit). MOI has 2 dits.

Correct pattern: -- --- ..

Sample explanation: "The letter I in Morse is two dits (..), but the pattern shown has only one dit (.). MOI should end with two short pulses, not one. The MO prefix (-- ---) is correct — the error is in the letter after MO."

Exercise 2

DIT=240, DAH=80 — what is wrong?

What is wrong: The values are swapped. A dah must be 3× a dit. With DIT=240 and DAH=80, dits would be longer than dahs, reversing the entire code.

Correct values: DIT=80 ms, DAH=240 ms.

Sample explanation: "The ratio DAH/DIT = 3 is a fundamental rule of Morse code. With the swapped values, short marks become long and long marks become short, making every message sound completely different. A scout listening in the field would decode the wrong beacon ID."

Exercise 3

You hear –– ––– · · · — which beacon?

Answer: MOS (Morse for M, O, S = M is --, O is ---, S is ...).

Sample explanation: "The long MO prefix (–– –––) is the same for all five beacons. After MO I count 3 short pulses (dits). Three dits = the letter S. So this is beacon MOS, the 3rd beacon in the cycle. In the field I would mark this bearing as Beacon 3."

Tier 3 — Complete Working playMorse Function

Below is the full reference implementation. Scouts should produce something functionally equivalent.

function playMorse(pattern) {
  var DIT = 80;   // milliseconds
  var DAH = 240;
  var GAP = 80;   // inter-element gap
  var CHAR_GAP = 240; // inter-character gap (space between letters)

  var ctx = new (window.AudioContext || window.webkitAudioContext)();
  var t = ctx.currentTime + 0.05; // small lead-in

  for (var i = 0; i < pattern.length; i++) {
    var ch = pattern[i];

    if (ch === ' ') {
      // Space between Morse characters (e.g., between M, O, and E)
      t += CHAR_GAP / 1000;
      continue;
    }

    var dur = ch === '-' ? DAH / 1000 : DIT / 1000;

    var osc = ctx.createOscillator();
    osc.type = 'sine';
    osc.frequency.value = 700;  // 700 Hz standard ARDF tone
    osc.connect(ctx.destination);
    osc.start(t);
    osc.stop(t + dur);

    t += dur + GAP / 1000; // advance time: tone + gap
  }

  // Auto-close context after all tones finish
  var totalMs = (t - ctx.currentTime) * 1000 + 200;
  setTimeout(function () { ctx.close(); }, totalMs);
}
Accept any implementation that correctly schedules AudioContext oscillators at 700 Hz with DIT≈80 ms and DAH≈240 ms. The exact gap handling (space vs. | separator) varies by string parsing approach.

Tier 4 — Extension Example (Speed Control + Visual Indicator)

// ── HTML needed: ──────────────────────────────────────────────────────
// <div id="morseIndicator" style="
//   width:60px; height:60px; border-radius:50%;
//   background:#333; transition:background .05s;

// <select id="speedSelect">
//   <option value="0.5">0.5× Slow</option>
//   <option value="1" selected>1× Normal</option>
//   <option value="2">2× Fast</option>
// </select>

// ── Extended playMorse ─────────────────────────────────────────────────
function playMorseExtended(pattern) {
  var speed = parseFloat(document.getElementById('speedSelect').value) || 1;
  var DIT = 80  / speed;
  var DAH = 240 / speed;
  var GAP = 80  / speed;
  var CHAR_GAP = 240 / speed;

  var ctx = new (window.AudioContext || window.webkitAudioContext)();
  var t = ctx.currentTime + 0.05;
  var indicator = document.getElementById('morseIndicator');

  for (var i = 0; i < pattern.length; i++) {
    var ch = pattern[i];
    if (ch === ' ') { t += CHAR_GAP / 1000; continue; }

    var dur = ch === '-' ? DAH / 1000 : DIT / 1000;
    var isDah = ch === '-';

    // Visual indicator scheduling
    (function(startT, d, dah) {
      setTimeout(function() {
        indicator.style.background = '#02ADA5';
        indicator.style.borderRadius = dah ? '8px' : '50%';
        indicator.style.width  = dah ? '120px' : '60px';
      }, startT * 1000);
      setTimeout(function() {
        indicator.style.background = '#333';
        indicator.style.width = '60px';
        indicator.style.borderRadius = '50%';
      }, (startT + d) * 1000);
    })(t - ctx.currentTime, dur, isDah);

    var osc = ctx.createOscillator();
    osc.type = 'sine';
    osc.frequency.value = 700;
    osc.connect(ctx.destination);
    osc.start(t);
    osc.stop(t + dur);
    t += dur + GAP / 1000;
  }

  var totalMs = (t - ctx.currentTime) * 1000 + 200;
  setTimeout(function () { ctx.close(); }, totalMs);
}

✍ 5. Reflective Journal Rubric

Minimum 15 words per prompt. Use this rubric to provide qualitative feedback.

PromptDeveloping (1)Proficient (2)Exceeds (3)
1. What surprised you about Morse timing? Names a fact without reflection. Expresses genuine surprise with reasoning. Connects surprise to a broader principle (e.g., importance of standards).
2. How would you remember beacons in the field? Repeats the mnemonic given. Proposes a personal memory strategy. Creates an original system with justification.
3. What would you change about ARDF beacons? Vague suggestion without reasoning. Specific change with rationale. Considers trade-offs and constraints of the change.
4. Morse code and computational thinking. Mentions "it's like code." Applies decomposition or abstraction correctly. Links multiple CT concepts (decomposition, pattern recognition, algorithms).
5. Sound patterns in other situations. Lists examples without explanation. Explains how the principle transfers. Novel, creative application with mechanistic reasoning.
Journals are not auto-graded. Use them for one-on-one check-ins or group discussion. Look for understanding of the why behind Morse timing, not just pattern recall.

⚠️ 6. Common Mistakes Table

IssueSeverityFix
Scout swaps DIT and DAH values (240ms / 80ms) High Remind: dah = 3× dit. DIT=80, DAH=240 always. The mnemonic is "dit is quick, dah is drawn out."
No inter-element gap between symbols Medium Each symbol must be followed by a GAP (=DIT) of silence before the next oscillator starts. Show the scheduler advancing time: t += dur + GAP/1000.
AudioContext created outside click handler (blocked) High Browser autoplay policy requires AudioContext to be created inside a user gesture handler. Ensure it is inside the addEventListener('click', ...) callback.
Oscillator not connected to destination before start High Call osc.connect(ctx.destination) before osc.start(). No connection = no sound, no error.
Confusing MOE and MOI (1 vs. 2 dits) Low Count aloud. MOE ends in E (one dit), MOI ends in I (two dits). Use the mnemonic: Every=1, Indian=2.
Forgetting the rest period (MO) in the cycle Low After beacon 5 (MO5), there is a 60-second window where only MO is broadcast. Scouts must wait and not mistake the rest period for a sixth beacon.
Tier 3: using setTimeout instead of AudioContext scheduling Medium setTimeout is unreliable for audio timing (tab throttling, event loop jitter). Accepted for Tier 3 but note the issue. Award full marks; discuss accurate scheduling as a stretch topic.
Not suspending AudioContext between plays Low Multiple AudioContexts can accumulate. Encourage calling ctx.close() after use or reusing one context per session.

💡 7. Facilitation Tips

For scouts scared of electronics / new to coding

  • Start with the Morse player in the lesson — let them press ▶ Listen for all five beacons and just count dits aloud together.
  • Tier 1 (fill in the blanks) is fully accessible. Celebrate getting it right before moving to Tier 2.
  • For Tier 3, show the code reference tab first, walk through it line by line, then ask them to close the tab and type it from memory. This builds confidence.
  • Pair shy scouts with a partner for Tier 2 debug exercises — talking through the problem aloud helps enormously.
  • Use the physical tap-finger technique (short tap = dit, hold = dah) to make the abstract timing concrete.

For fast learners and scouts with prior coding experience

  • Challenge them to Tier 4 immediately — the speed control and visual indicator extension is non-trivial.
  • Ask them to explain the AudioContext scheduling model: why schedule all oscillators up front rather than use setTimeout?
  • Extension challenge: add an envelope (GainNode with attack/release) to smooth the clicks on each tone.
  • Ask: how would you encode an arbitrary text string as Morse (not just ARDF callsigns)?
  • For radio enthusiasts: discuss how actual ARDF beacons generate the 700 Hz tone on a VHF carrier wave.

Running the module outdoors

  • If devices are unavailable outdoors, print the Morse reference table and have scouts tap the patterns on a table with a finger.
  • The 12-second beacon identification drill: facilitator taps a pattern on a desk, scouts write the beacon name.
  • Set a real field exercise: one scout transmits (clapping), others identify the beacon — works well in pairs.
Screen time advisory: If your group has limited screen time, prioritise Tier 1 + Concept Check on-device, and run Tier 2 debug exercises as paper or verbal activities. The Morse player demo works well on one projected device for the whole group.
